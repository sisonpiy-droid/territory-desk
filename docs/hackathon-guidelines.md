# AI x Ops Hackathon: overview and rules (Oct 21, 2026)

Teams of 2 (Piyush and Garima). One case per team. We chose **Case 1**.

**Stage 1, online submission (one form per team):**
- Demo video link of the working MVP (1 minute)
- Link to the MVP (no-code, low-code or code all welcome)
- Deck of exactly 8 slides covering problem breakdown, assumptions and adoption rollout

**Submission deadline (told to us by the team): Monday 26 October 2026, morning.**

**Stage 2, live presentation:** top 10 teams per class section present and demo, then Q&A. Scores are compared only within each case. Each section's 10 include at least 4 teams per case. Mentors then reveal how real operators solved the problem.

## Scoring
| Criterion | Weight | Judged from |
|---|---|---|
| Problem breakdown and assumptions | 20% | Deck (slides 2 to 4) |
| Adoption rollout | 15% | Deck (slides 6 and 7) |
| MVP: how well it solves the problem (not technical depth) | 35% | Video and MVP link |
| Final deck: communication quality | 10% | Deck (structure, flow, visual clarity only) |
| Presentation | 20% | Live session (Stage 2) |

MVP (35%) is what happens when judges run the test data through the link; the video shows them how to use it.

## Link rules
- The MVP link must stay live and working until **Wednesday 28 October 2026, end of day IST**.
- Judges must be able to use it without a login, a password or our help.
- If paid or closed tools are used, credits, quotas, billing and access are our responsibility. A paywall, rate limit or expired session counts as "not working".

## Deck format: exactly 8 slides
1. Title: both names, the case, MVP link, video link
2. Problem breakdown: who has the problem, what it costs today, the sub-problems
3. Scope: which sub-problems we solve, which we leave out, and why
4. Assumptions and data: key assumptions and how we would check each in the real world
5. Solution and MVP: how it works end to end, in one simple diagram
6. Adoption: who uses it day to day, what changes for them, why they might resist
7. Rollout plan: pilot, phases, and the metrics that would prove it works
8. Open slide: anything extra, including one optional brownie-point add-on

Judges want on slides 6 and 7: who the user is, why they would switch from today's way, how the pilot runs, what happens when the tool gets something wrong, and which metric proves people actually use it. Adoption lens for tools used inside a company (Case 1): the ADKAR model (Prosci). Judges reward specific plans, not framework headings.

## Optional brownie points (pick any one, slide 8, only separates close scores)
- Features we would build next
- Challenges we foresee at scale
- What else the build could be repurposed for
- What it would cost to run at real volume
